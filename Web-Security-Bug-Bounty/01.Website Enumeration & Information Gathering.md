## Website Enumeration & Information Gathering

The first and most critical step in web pentesting. The more you know about a target, the better your chances of finding a vulnerability. Rushing into attacks without proper recon is how you miss easy wins.

**Goal:** Build a complete picture of the target — what it's running, what's exposed, and where the weak points might be.

[+] **more information = better attack surface.**

**What you're looking for:**
- Server software and versions (Apache, Nginx, IIS)
- Hidden directories and files
- Login pages with weak input filtering
- Subdomains and related infrastructure
- Technologies used (PHP, WordPress, frameworks)
- Misconfigurations and exposed sensitive files

---

### Types of Scanning

**Active Scanning**
Directly interacting with the target — sending requests, probing ports, running tools against the server. Leaves traces in server logs. Examples: Nmap, Nikto, Dirb, Burpsuite.

**Passive Scanning**
Gathering information without touching the target directly. Uses third-party services and public data. Examples: Google Dorks, Shodan, WHOIS lookups, DNS records. Target never knows you looked.

---

| | Active | Passive |
|--|--------|---------|
| Target awareness | Yes | No |
| Information depth | Deep | Shallow |
| Speed | Fast | Moderate |
| Risk of detection | High | None |

---

## Tools To Be Used

| Tool | Type | Purpose |
|------|------|---------|
| **Google Dorking** | Passive | Find hidden pages, files, and vulnerabilities via search operators |
| **nslookup** | Passive | Resolve domain names to IP addresses, check DNS records |
| **Nmap** | Active | Port scanning, service detection, OS fingerprinting |
| **Nikto** | Active | Web server vulnerability scanner |
| **Dirb** | Active | Directory and file brute-forcing |
| **Burpsuite** | Active | Intercept and analyze HTTP requests/responses |

#### Google Dorking

Advanced Google search operators to find exposed files, login pages, emails and sensitive information indexed publicly.

```
# Find specific file types on a site
site:www.netcad.com filetype:pdf

# Find emails not listed on the official site
"@tesla.com" -site:www.tesla.com
Result: hello@tesla.np (found one external email)

# Find admin pages
intitle:admin OR inurl:admin site:www.facebook.com
# Found admin-related titles
```

More Google dork commands: [Exploit-DB Google Hacking Database](https://www.exploit-db.com/google-hacking-database)

---

#### Finding IP Address of a Website

**ping** — checks if host is up and finds IP:
```bash
ping facebook.com

PING facebook.com (57.144.176.1) 56(84) bytes of data.
64 bytes from edge-star-mini-shv-04-bom2.facebook.com: icmp_seq=1 ttl=64 time=46.9 ms
```
Note: Some websites block ping probes — don't rely on it alone.

**host** — finds all IP addresses (useful since big sites have many servers):
```bash
host tesla.com

tesla.com has address 2.18.52.207
tesla.com has address 2.18.53.207
tesla.com has address 2.18.54.207
tesla.com has address 23.7.244.207
```

**nslookup** — similar to host, may reveal additional DNS info:
```bash
nslookup tesla.com

Server: 192.168.18.1
Address: 192.168.18.1#53

Name: tesla.com
Address: 2.18.51.207
Name: tesla.com
Address: 2.18.50.207
```

**whois** — searches publicly available registration data about a domain:
```bash
whois tesla.com

Domain Name: TESLA.COM
Registrar: MarkMonitor Inc.
Creation Date: 1992-11-04
Registry Expiry Date: 2026-11-03
```
Can reveal registrar, creation date, expiry, sometimes contact info.

---

**IP Lookup sites** — give physical location, ISP, country from an IP:
- [whatismyipaddress.com/ip-lookup](https://whatismyipaddress.com/ip-lookup)

**whatweb** — discovers technologies behind a website (server, frameworks, plugins, versions):
```bash
whatweb 192.168.18.242 -a3 -v

Status    : 200 OK
Title     : owaspbwa OWASP Broken Web Applications
IP        : 192.168.18.242

Detected Plugins:
[ Apache ] + version info
```
Older versions of detected plugins may have known vulnerabilities — note them for later.

Aggression levels: `-a1` passive (one request), `-a3` aggressive (more requests, more info). Only use aggressive levels on authorized targets.

---

#### Dirb — Hidden Directory Discovery

Brute-forces directory names against a wordlist to find hidden pages:
```bash
dirb http://192.168.18.242 /usr/share/wordlists/dirb/common.txt
```

Wordlists are located at `/usr/share/wordlists/` in Kali Linux.

**Results on OWASP BWA:**
```
+ http://192.168.18.242/.bash_history     ← exposed shell history
+ http://192.168.18.242/cgi-bin/
+ http://192.168.18.242/crossdomain.xml
==> DIRECTORY: http://192.168.18.242/evil/
==> DIRECTORY: http://192.168.18.242/gallery2/
+ http://192.168.18.242/index.html
```

`.bash_history` being exposed is a serious misconfiguration — it can contain commands with passwords and sensitive paths typed by the server admin.

## 03. Scanning & Enumeration — Nmap & Nikto

---

### Nmap

Port scanner that finds open ports, running services, versions, and vulnerabilities. Essential first step after finding the target IP.

---

**Simple scan** — scans first 1000 ports by default:
```bash
nmap 192.168.18.242

PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
139/tcp  open  netbios-ssn
143/tcp  open  imap
443/tcp  open  https
445/tcp  open  microsoft-ds
8080/tcp open  http-proxy
8081/tcp open  blackice-icecap
```

To scan all 65536 ports:
```bash
nmap -p- 192.168.18.242
```

---

**SYN scan** — stealthy, doesn't complete the TCP handshake so leaves fewer traces. Also scans service versions with `-sV`:
```bash
nmap -sS -sV 192.168.18.242

PORT     STATE SERVICE     VERSION
22/tcp   open  ssh         OpenSSH 5.3p1 Debian
80/tcp   open  http        Apache httpd 2.2.14 (Ubuntu) PHP/5.3.2
139/tcp  open  netbios-ssn Samba smbd 3.X - 4.X
443/tcp  open  ssl/http    Apache httpd 2.2.14
8080/tcp open  http        Apache Tomcat/Coyote JSP engine 1.1
8081/tcp open  http        Jetty 6.1.25
```

Old versions = potential vulnerabilities. Apache 2.2.14 and PHP 5.3.2 are extremely outdated.

**Noisy scan** `-sT` — completes the full TCP handshake, leaves clear traces in server logs. Avoid on real targets unless authorized.

---

**Vulnerability scan** — uses Nmap scripts to detect known vulnerabilities:
```bash
nmap --script vuln 192.168.18.242
```

**Results on OWASP BWA:**
```
/wordpress/wp-login.php  ← WordPress login exposed
/phpmyadmin/             ← phpMyAdmin exposed
/cgi-bin/                ← potentially interesting

VULNERABLE: Apache byterange filter DoS
CVE: CVE-2011-3192
The Apache web server is vulnerable to a denial of service attack
when numerous overlapping byte ranges are requested.

http-internal-ip-disclosure: Internal IP Leaked: 127.0.1.1
```

Nmap found a real CVE automatically. This is why version scanning matters — old software = known exploits.

---

**Nmap scan types summary:**

| Flag | Type | Stealth | Speed |
|------|------|---------|-------|
| (none) | TCP Connect | Low | Fast |
| `-sS` | SYN Scan | High | Fast |
| `-sT` | TCP Connect | None | Slow |
| `-sV` | Version Detection | Medium | Medium |
| `--script vuln` | Vulnerability Scan | Low | Slow |

---

### Nikto

Web server scanner — automatically checks for outdated software, misconfigurations, dangerous files, and known vulnerabilities.

**Scan port 80 (default):**
```bash
nikto -host 192.168.18.242
```

**Scan specific port:**
```bash
nikto -host 192.168.18.242 -port 443
```

**Results on OWASP BWA:**
```
Apache/2.2.14        → outdated (current: 2.4.66)
PHP/5.3.2            → outdated (current: 8.5.1)
OpenSSL/0.9.8k       → outdated (current: 3.6.0)
Python/2.6.5         → outdated (current: 3.13.1)
mod_ssl/2.2.14       → outdated
/icons/              → directory indexing found
/cgi-bin/            → directory indexing found
```

Almost every component is outdated — each one is a potential attack surface.

**On port 443 (HTTPS):**
```
SSL Certificate: CN=owaspbwa (self-signed)
Cipher: DHE-RSA-AES256-SHA
```
Self-signed certificate means no trusted CA verified it — another misconfiguration.

---

### Key Takeaways

- Always run both `-sS -sV` and `--script vuln` — version info alone tells you what to search for in ExploitDB
- Nikto takes longer but finds things Nmap misses — outdated modules, misconfigurations
- Nikto scans port 80 by default — always scan 443 separately for HTTPS targets
- Old software versions are the most reliable attack vector — they have public CVEs with working exploits

## 04. Burpsuite

A web proxy tool for manual web application testing. Sits between your browser and the target website, intercepting every HTTP request and response so you can read, modify, and replay them.

---

### Setup

Set browser proxy to `127.0.0.1:8080` — all traffic routes through Burpsuite automatically.

---

### Key Tabs

**Proxy — Intercept**

Catches HTTP requests before they reach the server. You can read and modify anything — parameters, cookies, headers, body — then forward the modified request.

Use cases:
- Change `id=2` to `id=1` (IDOR)
- Change `role=guest` to `role=admin` (privilege escalation)

**Repeater**

Send the same request multiple times with modifications. Shows both request and response side by side.

Use cases:
- Try different parameter values
  
*Not yet used in practice — will update when practiced.*

**Intruder**

Automated attack tool — brute forces parameters using wordlists.

Use cases:
- Brute force login passwords
  
Attack types:
- **Sniper** — one payload list, one position (know username, brute password)
- **Cluster Bomb** — two payload lists, two positions (unknown username and password)

Find successful login by response **length difference** — correct credentials return a different sized response than failed ones.

---

### Workflow

```
Browser makes request
→ Burpsuite intercepts it
→ You read/modify the request
→ Forward to server
→ Server responds
→ You read the response
```

---

### Already Used In Practice

- Intercepted requests to modify cookies (`role=guest` → `role=admin`)
- Used Intruder with Cluster Bomb to brute force DVWA login
- Identified correct credentials by response length difference (4985 vs 4919)
- Intercepted ShellShock CGI request and modified User-Agent header
