# XML

XML (Extensible Markup Language) is structurally similar to HTML, but their purposes differ: while HTML uses predefined tags to render pages, XML allows you to define custom tags to store and transport data in a hierarchical, tree-like structure. XML prioritizes data portability and human readability over raw processing speed.

**Example:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<bookstore>
  <book category="fiction">
    <title>The Great Adventure</title>
    <author>Jane Doe</author>
    <year>2023</year>
    <price>29.99</price>
  </book>
</bookstore>
```

---

## XPath Injection

XPath Injection is similar to SQL injection — the input field is not properly sanitized, allowing XPath queries to pass through. Here, XPath directly points to nodes in the XML structure to retrieve specific data.

---

## What is XPath?

XPath is a query language used to navigate and select nodes in an XML document. It works like a path system — you describe the location of the data you want, and XPath retrieves it.

For example, in the XML above:
```
/bookstore/book/title
```
This means: start at the root, go to bookstore, then book, then return the title.

XPath can also filter by conditions:
```
/bookstore/book[price>20]/title
```
Returns titles of books costing more than 20.

---

## How XPath Injection Works

When a web application uses XPath to query XML data (for example, during login), the input is often concatenated directly into the query.

**Normal query:**
```
//user[username='INPUT' and password='INPUT']
```
**Injection:**
```
' or '1'='1
```
**Resulting query:**
```
//user[username='' or '1'='1' and password='']
```
Since '1'='1' is always true, the condition bypasses authentication — same concept as SQL injection, just targeting XML instead of a database.

# XXE (XML External Entity)

## Overview

XXE is a vulnerability where an attacker abuses the XML parser's ability to process external entities. By defining an external entity and pointing it toward a sensitive file or resource, the attacker can retrieve its contents or make the server perform unintended requests.

### Step 3: Craft the Payload

To make the payload work, we need to:

1. Declare `<!DOCTYPE any_name>`
2. Define an external entity pointing to a file
3. Use the entity (`&xxe;`) inside the XML so it reflects in the response

**Payload:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE hek [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<reset>
  <login>&xxe;</login>
  <secret>Any bugs?</secret>
</reset>
```
**Why this works:**
- `<!DOCTYPE hek [...]>` declares the DTD (Document Type Definition)
- `<!ENTITY xxe SYSTEM "file:///etc/passwd">` defines an external entity that reads the file
- `&xxe;` inside `<login>` forces the parser to substitute the entity — which contains the file's contents

In the request, change the `bee` value inside `<login>` to `&xxe;` — this is where the entity gets called and reflected.

## Key Takeaways

- XXE abuses the XML parser's ability to resolve external entities
- `SYSTEM` keyword is required for external entities
- The entity must be used (`&xxe;`) inside the XML for it to reflect in the response
- Attacker can read files, perform SSRF, or cause DoS
- Mitigation: disable external entity processing in the XML parser
